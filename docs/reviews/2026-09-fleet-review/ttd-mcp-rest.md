# ttd-mcp review (REST half + package-wide consistency)

Scope: the REST CRUD, bulk, bid-list, seed, preview, upload, pacing and context tools; all reporting tools that are not `graphql-*.tool.ts` (REST MyReports plus the GraphQL-backed MyReports template, schedule and entity-report tools); and package-wide config, auth, session, retry, rate limit and sandbox routing. The GraphQL passthrough and bulk tools (`graphql-*.tool.ts`) are covered by the sibling review. Nothing in the repo was modified.

## Summary

The package is structurally in good shape. All 46 tools are registered in `allTools`, none are orphaned, all names are prefixed, `ttd_search_tools` is present, governed writes carry consistent `cesteral` blocks, and auth fast-fail validation and session services follow the fleet pattern. The problems are behavioural bugs and a lot of drift in the tool descriptions an LLM reads. Top issues:

1. **Default rate limiter vs. batch limits.** The default rate limiter (60/min, one process-wide key `ttd:direct-token`, and it throws instead of waiting) guarantees partial failure on `ttd_bulk_update_status` and `ttd_archive_entities`, which accept 100 IDs. It also puts every HTTP tenant in the same bucket.
2. **Sandbox can silently write to production.** With the shipped `.env.example`, `TTD_USE_SANDBOX=true` moves only GraphQL to the sandbox. `.env.example` pins `TTD_API_BASE_URL` to production, so REST writes still go to production, where campaigns spend real money.
3. **List pagination probably stops after page 1.** `listEntities` reads `TotalCount`. The package's own `types.ts` and TTD Foundations name the field `TotalFilteredCount`. If `TotalCount` is absent, `nextPageToken` is never emitted, so pagination stops after the first page with no error.

Also notable:
- Several tool descriptions tell the model the wrong thing. `adjust_bids` and `bulk_update_status` say they do GET→PUT (the code does a partial PUT). `bulk_update_entities` says PUT replaces the whole entity. `upload_video` points to a nonexistent `ad` entity type. `duplicate_entity` says TTD has no copy API.
- `ttd_manage_bid_list` and `ttd_bulk_manage_bid_lists` never check GraphQL errors, so a failure is reported as success and still emits a governed effect.
- `submit_report` / `get_report` without `advertiserIds` produce a schedule that `check_report_status` can never poll.
- Terminal operations can be reached without being declared terminal: bid-list delete, and archive via `bulk_update_status` or `update_entity`.

**Doc reachability:** every official TTD host (`partner.thetradedesk.com`, `open.thetradedesk.com`, `api.thetradedesk.com`, `desk.thetradedesk.com`, `ext-api.sb.thetradedesk.com`) is blocked by the egress proxy (WebFetch `EGRESS_BLOCKED`; curl CONNECT 403). The sources I could use were:
- TTD's official public sample repo `github.com/thetradedesk/platform` (HEAD adff1a6, 2025-06-23), cloned read-only into scratchpad.
- The vendored docs in `packages/ttd-mcp/docs/api/`. They say they were generated from open.thetradedesk.com on 2026-05-14 and from the partner portal on 2026-04-14. Neither was fetched live today.
- WebSearch snippets.

No claim below is marked live-doc verified.
