# meta-mcp review

## Summary

The package's structure is sound. All 27 tools are registered and match `registry.json`. Governance blocks are present on every write. The suite passes: 45 files and 686 tests, run with `npx vitest run` and with no changes to the repo. The weak points are the Meta-specific details. Several enums and parameter formats sent to Meta are wrong, pagination is broken in most list and report tools, and some reporting math is incorrect.

Top issues:
1. **Pagination never ends (bug).** `meta_list_entities`, `meta_list_ad_accounts`, `meta_get_insights` and `meta_get_insights_breakdowns` use `paging.cursors.after` to decide whether more pages exist. Meta also returns that cursor on the last page, so `hasMore`/`has_more` is always true and a "more rows" warning is always added. The package's own `meta_search_targeting` does this correctly by checking for `paging.next`.
2. **Wrong values are sent to Meta.**
   - `meta_duplicate_entity` sends `status_option: "INHERITED"`. The API value is `INHERITED_FROM_SOURCE`.
   - `meta_manage_budget_schedule` documents `budget_value_type: ABSOLUTE|RELATIVE` with ISO-8601 times. The API takes `ABSOLUTE|MULTIPLIER` with Unix timestamps.
   - Rate-limit error codes 613 and 80000–80014 (the Business Use Case codes, which come back as HTTP 400) are not classed as rate limits. They are neither retried nor mapped to `RateLimited`.
   - Tool text and resources still list the `7d_view` attribution window, which Meta removed on 2026-01-12. `CONVERSIONS` and `campaign_budget_optimization` still appear as usable values.
   - The campaign-create examples omit `is_adset_budget_sharing_enabled`, which v24+ requires for campaigns with no campaign-level budget.
3. **Wrong reporting numbers.**
   - `includeComputedMetrics` in `get_insights` and `get_insights_breakdowns` adds up `purchase`, `offsite_conversion.*`, `lead` and similar together. These overlap in Meta's `actions` array, so CPA and ROAS are counted more than once. This is from model knowledge.
   - In `download_report`, each row is flattened with `String(v)` before metrics are computed. `actions` becomes `"[object Object]"`, conversions come out as 0, and the returned rows lose their arrays.
4. **The rate limit and the bulk tools contradict each other.** The default limit is 20 requests per minute (README says 200), and each write costs 3 tokens. That allows about 6 writes a minute per key, but the bulk and bid tools advertise "max 50".

**Doc reachability:** every official Meta host was blocked by the egress proxy (developers.facebook.com, developers.meta.com), as were the third-party blogs I tried to open (kitchn.io, unalsoft.com). Version, sunset and field facts below come from WebSearch result snippets only: official blog titles plus third-party pages. None of it is marked live-doc verified.
