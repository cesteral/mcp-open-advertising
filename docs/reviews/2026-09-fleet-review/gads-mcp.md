# gads-mcp review

## Summary
The package's structure, governance annotations and auth plumbing are tidy. Its data path does not work against the pinned v23 API, and the reasons below were checked against Google's own **live v23 Discovery document**. The mocked tests do not catch either problem.

1. **Critical:** every GAQL read sends `pageSize` in the `googleAds:search` body. The v23 Discovery doc says "Google Ads API returns a `PAGE_SIZE_NOT_SUPPORTED` error if this field is set". This breaks `gaql_search`, `list_entities`, `get_entity`, `get_insights`, `get_ad_preview`, `duplicate_entity`, the `adjust_bids` read, and every before/after snapshot.
2. **Critical:** `campaign.start_date` / `campaign.end_date` exist in v22 but were removed in v23 (they are now `start_date_time` / `end_date_time`, formatted `yyyy-MM-dd HH:mm:ss`). The default campaign SELECT, the create/update examples, the entity-schema resource, the prompts and the snapshot builder all still use the old names.
3. **High:** nothing covers the EU political-advertising declaration (`containsEuPoliticalAdvertising`). v23 carries `mutateError.EU_POLITICAL_ADVERTISING_DECLARATION_REQUIRED` ("Mutates are generally not allowed if the customer contains non-exempt campaigns without the EU political advertising declaration").

Other issues:
- An upstream 401 is mapped to `InvalidRequest`, so dead sessions are never dropped.
- The 10-requests-per-minute limiter makes `adjust_bids`' "up to 50" fail after about 5 ad groups.
- The descriptions point to a `generateAdPreview` API that does not exist.
- `LAST_90_DAYS` is offered as a date preset but is not a GAQL literal.
- Several capability claims are stale: "no binary video upload", "assets create-only", "no asset validateOnly".

**Version:** v23 is still served today; v20 and v21 return 404. The latest version is v25 (v25.2).

**Doc reachability:**
- `developers.google.com` and `ads-developers.googleblog.com` are blocked by the egress proxy (403 CONNECT).
- Google's machine-readable **Discovery service** (`googleads.googleapis.com/$discovery/rest?version=vNN`) and the official `googleads/google-ads-python` ChangeLog (GitHub) and PyPI metadata are reachable, and were used as the primary live sources.
- The sunset dates come only from third-party search results.

## Open questions
1. Has anyone exercised this server live since the v23 bump? There is no `verification.json`, so every tool is `declared`. #1 and #2 suggest not.
2. Does GAQL accept a quoted integer (`campaign.id = '123'`)? `buildListQuery` quotes any operator-less filter value. This is unverified because the grammar page is blocked.
3. What input does `customers:generateShareablePreviews` take (asset group vs ad)? It decides whether #6 can be implemented rather than just removed.
4. Is v23's exact sunset date February 2027? That comes from third-party sources only. The official sunset-dates page needs a reachable host or a human check before platform-facts is marked `verified`.
5. Should the terminal-operations ratchet (#8) cover the other servers' `*_bulk_update_status` tools that accept DELETED, REMOVED or ARCHIVED? This is likely a fleet-wide gap, but it was not checked outside gads.
