# msads-mcp review

## Summary

The package targets the right API surface. Microsoft Advertising API **v13 REST/JSON** is still the latest version: there is no v14, the SOAP API is deprecated on 2027-01-31, and new features ship REST-only from 2026-10-01. The three base hosts/paths are the documented REST ones, and 34 of the 36 CRUD paths/verbs in `entity-mapping.ts` match the docs exactly. Almost every write path outside a single-entity `create` is broken or misleading, though. Tests mock the HTTP client and never assert request bodies or paths, so none of these problems were caught.

**Top 3 issues:**
1. **Parent/account IDs are dropped from write bodies.** `update_entity`, `bulk_create_entities`, `bulk_update_entities`, `bulk_update_status` and `adjust_bids` send `{ Campaigns|AdGroups|Ads|Keywords: [...] }` with no `AccountId` / `CampaignId` / `AdGroupId`. The documented request bodies for Add/Update of those entities carry those fields, and the tools give the caller no way to supply them.
2. **`adjust_bids` writes `Bid: 1.5`, but `Bid` / `CpcBid` are `Bid` objects (`{"Amount": 1.5}`).** The service test expects the scalar, so the bug is locked in by a test.
3. **Four tools call things that don't exist or aren't what they say:**
   - `manage_ad_extensions` `setAssociations` posts to `/AdExtensionsAssociations`. The documented path is `/AdExtensionsAssociations/Set`.
   - `import_from_google` `getResults` posts to `/ImportResults/QueryByIds`. The documented path is `/ImportResults/Query`.
   - `create_report_schedule` sends a `Schedule` element that doesn't exist on `ReportRequest`, so it creates a one-off report and calls it a "schedule".
   - `delete_report_schedule` is a no-op that logs, while `registry.json` says it "Deletes the schedule and its future runs".

Also confirmed:
- `list_entities` / `get_entity` for campaigns only return **Search** campaigns unless `CampaignType` is passed. This is the documented default.
- The AgeRange enum value is misspelled: the code has `ThirtyFiveToFortyNine`, the API has `ThirtyFiveToFourtyNine`.
- Several field-rule enums are invalid, so `msads_validate_entity` rejects valid values.

**Doc reachability:**
- `learn.microsoft.com` is blocked by the egress proxy (WebFetch: `EGRESS_BLOCKED`).
- `github.com` web and `api.github.com` return 403.
- **`git clone` over HTTPS works.** I sparse-cloned `MicrosoftDocs/Advertising`, the current source of learn.microsoft.com/advertising (HEAD `166b995`, 2026-09-23), and `BingAds/BingAds-Python-SDK` (13.0.29). Every "live-doc" claim below was read from that mirror.
- This also means the 3 `msads.*` platform-facts can now actually be checked. See Open questions.

## Open questions

1. **Required-ness of parent IDs on Update/Add (#1-#4).** The REST reference tables have no "required" column, and the SDK REST models mark everything optional. The docs list `AccountId` / `CampaignId` / `AdGroupId` as body elements, the header doc implies AccountId is required on the operations that take it, and historically (SOAP) these were required. A single sandbox call (`campaign.api.sandbox.bingads.microsoft.com`) would settle it; no credentials were available here.
2. **REST `AdTypes: null` / audience `Type` omission.** Do GetAdsByIds/GetAdsByAdGroupId accept a null `AdTypes`, and does GetAudiencesByIds work without `Type`? Undocumented either way.
3. **REST flag-enum encoding.** For `CampaignType` flags in JSON (needed for #9): space-delimited like SOAP, comma-delimited, or an array? The Request JSON sample shows a single `"ValueHere"`.
4. **HTTP status for throttling (error 117) in REST.** Is it 429, 400 or 500? This determines whether the default retry predicate covers it.
5. **Is the GitHub mirror (`MicrosoftDocs/Advertising` via `git clone`) acceptable as the verification source for platform-facts?** It is the literal source of learn.microsoft.com/advertising, so the "learn.microsoft.com is unreachable" premise in CLAUDE.md no longer blocks verifying the 3 `msads.*` facts. That is a ledger-owner decision; nothing was changed.
6. **Microsoft's first-party Microsoft Advertising MCP Server (docs 2026-07-22).** Worth a product decision on overlap. Not a defect.
7. **Low-priority capabilities the package doesn't cover.** LinkedIn segment targeting (`CustomLinkedInCriterion`, `GetLinkedInSegments`, Aug 2026), `AISearchSetting` (May 2026), Performance Max asset groups, `GetAdExtensionIdsByAccountId`, Bulk service (the recommended path for large-scale writes per `services-protocol.md`), `EditorialRejections/Appeal`, `GetOfflineConversionReportByGoalIds`, BidStrategy report, and SearchTermLandingPage / MSClickIdPerformance reports. The `Campaign.IsPolitical` flag (EU 2024/900) defaults to false on Add/Update, so no change is required.
