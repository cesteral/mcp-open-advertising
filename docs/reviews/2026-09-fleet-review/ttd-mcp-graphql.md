# ttd-mcp review: GraphQL half

Scope: `ttd_graphql_query`, `ttd_graphql_query_bulk`, `ttd_graphql_mutation_bulk`, `ttd_graphql_bulk_job`, `ttd_graphql_cancel_bulk_job`; `TtdService.graphqlQuery` / `TtdHttpClient.fetchDirect`; the `{ __typename }` auth ping in `TtdDirectTokenAuthAdapter.validate()`; `graphql-errors.ts`; the `graphql-reference://ttd` resource and the GraphQL parts of the README and prompt. The REST tools and package-wide config belong to the sibling review. I note cross-references only where they touch GraphQL.

## Summary

The GraphQL surface follows the repo's conventions: one file per tool, all five registered, platform-prefixed names, effect-class `cesteral` blocks on the three writes, dry-run on the bulk writes, no 5xx retry on POST. **The bulk-job lifecycle, though, has never been exercised against TTD.** `verification.json` and the 2026-04-01 report both mark all four bulk tools "PASS (untested live)". The repo also gives two different, mutually exclusive descriptions of the bulk API. The official TTD SDK (reachable on GitHub) contradicts the status enum the tools publish.

Top 3 issues:
1. **`graphql-reference://ttd` documents a different bulk API from the one the tools call.** The resource says `bulkQuery(input:{query,variables}){jobId}` and `bulkJob(jobId:)` with `resultUrl/progress/errorMessage`. The tools send `createQueryBulk(input:{query,queryVariables})` and `bulkJob(id:)`, with `... on BulkQueryJob { url }`. At most one of these is right, and the resource claims it was "Last validated: 2026-04-14 via live API testing".
2. **The bulk-job status model is incomplete and at least partly wrong.** TTD's official Workflows SDK (whose `GraphQlBulkJob` model "mirrors the GQL bulkjob") lists statuses `QUEUED, IN_PROGRESS, PARTIAL_SUCCESS, FAILURE, SUCCESS, CANCELLED`, plus the fields `completionPercentage`, `rawResult`, `queryGqlErrors` and `runtimeErrors`. The tools advertise `RUNNING` and never mention `PARTIAL_SUCCESS`. The poll query selects no error or progress fields, even though the description promises "job progress". A partly failed, non-cancellable 1000-entity mutation job therefore shows up as a bare status with no diagnostics. On top of that, the tools send results to `ttd_download_report`, which only parses CSV.
3. **The `ttd_graphql_mutation_bulk` examples are almost certainly wrong.** `updateCampaign(input:){ campaign { campaignId name } }` and `updateAdGroup(...){ adGroup { adGroupId baseBidCPM } }` use verb-first names and REST field names. Every other TTD mutation in this package is `<entity><Verb>`, for example `bidListUpdate`, `seedCreate` and `campaignUpdateSeed`, with a `{ data, errors }` payload. The per-input shape also conflicts with the query-bulk example: that example keys entries by variable name, while this one keys them by input field. Separately, arbitrary delete or archive mutations run through this tool (and through `ttd_graphql_query`) are invisible to the terminal-operations ratchet and to `rollback.terminalOperations`.

Doc reachability: **every TTD host is blocked by the egress proxy** (CONNECT 403): `partner.thetradedesk.com` (all GraphQL doc pages), `desk.thetradedesk.com/graphql`, `api.thetradedesk.com` and `ext-api.sb.thetradedesk.com`. Introspection could not be attempted, auth-walled or not. The only primary source I could reach is TTD's own `github.com/thetradedesk/ttd-workflows-python` SDK (last commit 2026-04-24). It covers the Workflows REST facade over GraphQL bulk jobs, not the GraphQL schema itself. Every claim about GraphQL mutation names, input types or limits below is **UNVERIFIED** unless it is marked as corroborated by that SDK.

## Open questions

1. **What does `CreateQueryBulkInput` actually take?** The Workflows `GraphQlQueryJobInput` has only `query` (+callback, beta). The search-indexed text from GqlBulkOperations describes bulk query as fully iterating pagination and nesting into one output file. If `createQueryBulk` has no variable-set field, `ttd_graphql_query_bulk`'s core premise ("runs the same GraphQL query across many variable sets") and its `variables` parameter are wrong. This needs someone with Partner Portal access (or a sandbox call) to check GqlBulkOperations and the schema explorer (`https://partner.thetradedesk.com/v3/portal/api/graphql-schema`).
2. Are the bulk mutation names really verb-first (`createQueryBulk`, `createMutationBulk`, `cancelBulkJob`) when the rest of TTD's schema is noun-first (`bidListCreate`, `seedCreate`, `myReportsTemplateCreate`)? The SDK's `GraphQlBulkJobPayload {data, errors}` envelope fits either convention. Not decidable offline.
3. Does TTD report per-input failures of a mutation bulk job inside the result file, in `runtimeErrors`, or both? This decides how `ttd_graphql_bulk_job` should present PARTIAL_SUCCESS.
4. Is `bulkJob` a union or interface with concrete `BulkQueryJob` / `BulkMutationJob` types (as the tool assumes), or one object type (as the SDK model suggests)? If it is one type, the inline fragments on non-existent types fail validation and the poll tool is broken outright.
5.
