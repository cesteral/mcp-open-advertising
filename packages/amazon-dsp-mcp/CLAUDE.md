# amazon-dsp-mcp

Platform notes for this package: quirks that are easy to forget when editing it. Repo-wide conventions are in the [root CLAUDE.md](../../CLAUDE.md).

**Entity management is on the Unified API (#234)** — `POST /adsApi/v1/{create|update|query|delete}/{campaigns|adGroups|ads|targets|adAssociations}`, taken from Amazon's machine-readable `unified-api-dsp.json` (amzn/ads-advanced-tools-docs @ `e25aace0`). The tools keep the old entity-type names (`order` = campaign, `lineItem` = ad group, `creative` = ad, `creativeAssociation` = ad association) and every entity tool takes `accountId` (DSP advertiser ID) for the required `Amazon-Ads-AccountId` header; `/adsApi/v1/*` sends no `Amazon-Advertising-API-Scope` (the spec declares none; the DSP migration guide says "Not used"). Campaigns and ad groups can only be **created PAUSED**; `DSPUpdateState` is ENABLED | PAUSED, so ARCHIVED is refused on update. The spec has **no delete for campaigns / ad groups / ads**: `amazon_dsp_delete_entity` deletes targets and ad associations via Unified, archives orders / line items through the one legacy call still made (`PUT /dsp/orders|lineItems/{id}`), and refuses creatives. Targets cannot be read by ID or updated. `get_ad_preview` stays on legacy `/dsp/*` (no Unified equivalent). `list_advertisers` and session validation use `POST /adsApi/v1/query/advertiserAccounts` (the legacy `GET /dsp/advertisers` is deprecated, 404 from July 2027): it sends only `Amazon-Ads-ClientId`, returns **global accounts only** unless `isGlobalAccountFilter: { include: [false] }` is set, paginates by `nextToken` (a page can be empty and still carry one), and `maxResults` is 10..100. `accountId` on every other tool is the `dspAdvertiserId` in an account's `alternateIds`, not the `advertiserAccountId` (`amzn1.ads-account.g.*` would make entity queries require an ID filter, 400 from 2026-11-18) — `amazon_dsp.account_id_header_value`. **Nothing on this surface has been exercised against Amazon** (`platform-facts.json` `amazon_dsp.unified_entity_*`). Reporting v3 is scoped by `accountId` (DSP entity ID) in the URL path, distinct from the profile header. **Stdio auth prefers the LwA refresh-token flow** (`AMAZON_DSP_APP_ID` + `_APP_SECRET` + `_REFRESH_TOKEN` + `_PROFILE_ID`) — auto-refreshes the 60-min access token. Falls back to static `AMAZON_DSP_ACCESS_TOKEN` for short CI runs.
