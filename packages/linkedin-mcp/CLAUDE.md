# linkedin-mcp

Platform notes for this package: quirks that are easy to forget when editing it. Repo-wide conventions are in the [root CLAUDE.md](../../CLAUDE.md).

URN-based entity IDs, `LinkedIn-Version` pinned in `src/config/api-version.ts` (currently `202610`, basis `confirmed`: LinkedIn's migrations page lists it Active until 2027-10-15, and it is the latest), analytics via `/rest/adAnalytics` with pivot breakdowns. **The `/v2/` → `/rest/` migration is STAGED and incomplete (#210)**: list/create for campaigns and campaign groups are account-scoped under `/rest/adAccounts/{accountId}/…`, as are `adAccounts`, `adAnalytics`, `adTargetingFacets`, `adTargetingEntities`, `adSupplyForecasts`, `audienceCounts` and `adPreviews`. **Every item path (get/update/delete) is on `/rest/` and takes the owning account**, so `linkedin_get_entity`, `update_entity`, `delete_entity`, `duplicate_entity`, `bulk_update_status`, `bulk_update_entities` and `adjust_bids` have an `adAccountUrn` parameter (required for every type but `adAccount`; `src/mcp-server/tools/utils/ad-account-param.ts`). The paths are in `entity-mapping.ts` `itemRequest`: `/rest/adAccounts/{id}/adCampaigns/{numericId}`, `/adCampaignGroups/{numericId}`, `/creatives/{encoded creative URN}`, `/rest/adAccounts/{numericId}` for an ad account, and `/rest/conversions/{numericId}?account={urn}` for a conversion rule. A creative's status field is `intendedStatus` (`status` is refused for creatives; `bulk_update_status` sends `intendedStatus`). DELETE removes only DRAFT entities (anything else goes to `PENDING_DELETION` by update; the delete dry-run reports a non-DRAFT campaign as not deletable), and every DELETE sends `X-RestLi-Method: DELETE`. A conversion rule has no documented delete, so `delete_entity` does not offer one; an ad account and (until creative create migrates) a creative cannot be duplicated. `conversionRule` list is `GET /rest/conversions?q=account&account={urn}` (the `account` finder takes no `start`/`count`; a `search` finder 404s, #301) and create is `POST /rest/conversions`. Creative list/create stay on `/v2/adCreatives` (the Creatives API schema is a rewrite), and the Assets→Images/Videos upload split is untouched. **Targeting uses LinkedIn's names, and refuses the old ones** (`src/services/linkedin/targeting-facets.ts`): facets are `urn:li:adTargetingFacet:<camelCasePluralName>` (`locations`, `seniorities`, `staffCountRanges`, `employers` — not `geos`, `memberSeniorities`, `companySizes`, `organizations`), values are in LinkedIn's own namespaces (`urn:li:seniority:3`, `urn:li:industry:9` — not `urn:li:adSeniority:…`), and `linkedin_search_targeting` picks the `adTargetingEntities` finder from its arguments and refuses one a facet does not support (`locations`, `schools`, `employers*` are typeahead-only). `linkedin_get_delivery_forecast` is `GET /rest/adSupplyForecasts` and returns impressions/clicks/spend, **not an audience size** — `linkedin_get_audience_count` (`GET /rest/audienceCounts`, `total` is 0 below 300) is the audience size. `tests/mcp-server/linkedin-targeting-text.test.ts` fails if a resource, prompt or tool example names a retired facet or value namespace, a facet outside the documented table, or a tool call its own schema rejects. **Query strings are Rest.li 2.0** (`accounts=List(urn%3A…)`, `dateRange=(start:(year:…,month:…,day:…),end:(…))`) — every request sends `X-Restli-Protocol-Version: 2.0.0`, so pass arrays/records to `LinkedInHttpClient.get` and never 1.0 keys like `accounts[0]` or pre-encoded strings; `src/services/linkedin/restli-query.ts` is ported from LinkedIn's official `linkedin-api-js-client` encoder and tested against its vectors (`URLSearchParams` cannot express 2.0). **Nothing here has been exercised against LinkedIn.** LinkedIn's docs (`learn.microsoft.com/en-us/linkedin`) are fetchable and were read on 2026-10-01; what they settled is recorded in `platform-facts.json` as `verified` (analytics fields and pivots, cursor pagination, account-scoped item paths, the protocol header, the targeting facet and value URN namespaces, the `adTargetingEntities` finders, forecasts, audience counts and ad previews), and the rest stays `unverified` with its basis. Known mismatches still in the code, found in that read and tracked under #210: list tools send `start`/`count` where LinkedIn uses `pageToken`; creative list/create and uploads are on legacy paths; session validation calls `/v2/me`.
