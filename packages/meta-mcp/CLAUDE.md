# meta-mcp

Platform notes for this package: quirks that are easy to forget when editing it. Repo-wide conventions are in the [root CLAUDE.md](../../CLAUDE.md).

Graph/Marketing API `v26.0`. The hard-coded default field lists (entities, ad accounts, insights) and the insights catalog are checked against v26 field lists vendored from Meta's own `facebook-business-sdk-codegen` specs (`tests/fixtures/graph-v26-spec.json`, generated from the commit it records — regenerate it on a version bump, never hand-edit). Graph rejects a request naming a field its node lacks with `(#100)`, so one stale default breaks every default read. **Verified 2026-11-13 against Meta’s v26.0 changelog (#229, ledger `meta.v26_changes_apply_to_all_versions`); the three changes have different scopes.** `messenger_positions: ["story"]` is silently dropped on v26.0+, and from 2026-10-27 on every version including unversioned calls. `instagram_positions: ["explore"]` errors on v26.0+ only; Meta states no extension to earlier versions. For ad sets in the Housing, Employment and Financial special ad categories, creating one with relaxable, non-broad targeting on v26.0+ must set `targeting.targeting_automation.advantage_audience` explicitly (else `ADS_TARGETING__REQUIRE_EXPLICIT_ADVANTAGE_AUDIENCE_FLAG`); updates are unaffected, and it reaches older versions only once v25.0 is deprecated, date TBD. meta-mcp pins v26.0, so all three apply to its calls. It sends targeting unchanged but warns about them in response **text only** (#229, `tools/utils/v26-targeting-warnings.ts`): the dry-run and execute responses of `meta_create_entity`, `meta_update_entity`, `meta_bulk_create_entities` and `meta_bulk_update_entities`, and the dry run of `meta_duplicate_entity` (ad sets), add a "Warnings (non-blocking)" block; each message states its own scope. Nothing enters structured content: `validationErrors` and `wouldSucceed` are unchanged, because a governance consumer may treat any entry there as blocking, and a new output field would move the hash. The logic hands the warnings to the formatter through a WeakMap keyed by the result object, which the factory passes through unchanged. Check 3 (`advantage_audience`) is for creating and copying an ad set, so updates (single and bulk) do not check it and read no campaign. It needs the parent campaign's `special_ad_categories`: the duplicate dry run reads it (one rate-limited read, only when `advantage_audience` is unset); creates and bulk creates make no read, so there the text says the category was not checked. No shipped example names either placement or puts an ad set in a special ad category (every campaign example sends `special_ad_categories: []`), but most ad-set examples omit `targeting_automation`.
